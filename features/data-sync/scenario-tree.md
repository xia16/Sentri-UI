# Data sync — scenario tree

依据：U = 用户 2026-10-12 答复；L = mobile_webapp 旧版代码（参考，不自动成为新产品批准）；P = 本功能 PRD 的已裁决规则；H = 当前 Home 原型（旧行为，仅基线）。S 是有来源的分支，I 是按记录安全推断的分支。? Qn 没有预设结果，原型不能把问号画成已批准行为。

状态轴：记录 R0 未写入本机、R1 待同步、R2 发送中、R3 已同步、R4 失败、R5 冲突、R6 前置阻断、R7 已删除；网络 N0 无网络、N1 不稳定、N2 可同步；身份 A0 当前账号/猪场、A1 切换请求、A2 登录失效。入口：保存回执、首页本机记录入口、任务内待同步提示、工具箱离线数据。每条记录的状态独立，Home 的数字是这些状态的汇总。

## B · 自动同步与逐条结果

| # | State | Event | Result | Src | Leaf |
|---|---|---|---|---|---|
| B-1 | R1 N0 | 网络恢复到 N2 | → 无需点上传，进入发送中；发送中操作不重复触发 | S — U；L syncCoordinator | pending |
| B-2 | R1 N1 | 质量仍不稳定 | → 留在本机，状态说明等待可用网络 | S — L networkQuality 与 syncCoordinator | pending |
| B-3 | R2 N2 | 服务端确认成功 | → 该条变为已同步，有完成时间；待同步数减一 | S — L syncSingleCommand | pending |
| B-4 | 三条 R2 N2 | 两条成功、一条失败 | → 两条已同步、一条仍本机且显示失败原因；不可显示“整批完成” | S — L 逐条结算；P Rules | pending |
| B-5 | R2 | 发送中断或 5xx | → 保留本机记录，回待同步并安排自动重试；不得显示成功 | S — L errorClassifier、retry delay | pending |
| B-6 | R1 N2 | 连续快速点记录入口或手动重试 | → 同一操作只发送一次，不因双击多写 | I — 防重复写入；L syncing 锁 | pending |
| B-7 | R2 | App 关闭再打开，服务端已收到但本机未获回执 | → 保留本机并按同一操作 ID 查询；查到已处理才标已上传；查到未处理才用同一 ID 重试，查询未明继续等待 | S — U 服务端保证去重且可查 | pending |

| C-10 | 前置 R5 已删除、较晚 R6 | 再次自动同步 | → 后续记录继续受阻并保留本机，只可查看或逐条删除，不自动发送 | S — U 补充裁决 | pending |
| C-11 | 前置 R5 已删除、较晚 R6 | 查看后确认删除该受阻记录 | → 只删除这一条；无法恢复、不会上传，其他记录保持原状 | S — U 补充裁决 | pending |

## E · 95% line and handoffs

离线无缓存 → handoff:workbench；任务关闭条件 → handoff:workbench 及所属任务；业务更正 → handoff:pig-profile 或实际所属业务功能。人工强制跳过前置操作、其他非冲突记录删除、队列内编辑、跨设备合并、手动排序和开发网络覆盖器均按 operations.md 的 Not supported 结束，不生成可执行动作。

## Walk personas

第一次使用的工人：断网保存与首页回看（A）；巡检工人：弱网恢复、部分成功（B）；主管：失败、冲突、删除确认（C）；同一猪只连续操作的工人：前置阻断（C）；换班工人：重启、隔天、账号切换（D）；breaker：快速双击、断网后回网、发送中杀 App、第二台设备的更新、360 宽中文长耳号。
