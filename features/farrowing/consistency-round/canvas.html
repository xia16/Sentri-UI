Farrowing · consistency canvas · 17 Nov 2026

同一功能，从每个入口进入都应是同一版

每张手机画面均为 390 × 844，来自当前主线的真实原型及其组件；“new” 只在本画布脚本中用现有 SentriUI 部件拼出，尚未进入原型或 Atlas。这里先展示差异与建议，待负责人同意再同步。

1 · Actions 的入口指向了两个对象

Atlas 中 5 个 screen 的 “Actions” 先点中房间底栏；母猪记录中的 Actions 才是这些 screen 描述的入口。

建议 · 绑定修复

将 farrowing.sow-actions、.note、.piglet-care、.piglet-identity、.piglet-death 的起始步骤改为母猪记录上的 sowActions，再重放各自的动作。

不改这张 Actions 的已批准外观。

2 · 母猪 Note 没有跟上新版组件

同一原型的 pen note 与 Inspection 的 pig note 已有 7 天 Show for；母猪 Note 仍是旧表单。

待确认 · 备注时效

新版 Note 默认显示 7 天（可调 1–60 天）。母猪 Note 目前没有到期规则。死亡母猪的 Actions 已经用 Inspection 的新版 Note；活母猪的 Edit note 却走左侧旧表单。

建议各状态使用同一规则；保留 Back 草稿与历史记录。

3 · 同一窝仔猪有两张不同的列表

从死亡或完成母猪的记录进入 Piglets，是 11 月 3 日批准的 Row 选择面；从 Actions → Piglet processing 进入的 Piglet records 仍是旧页面。

待确认 · 页面归属

旧页面还混有 Care、身份录入和 Report mortality；features/piglet-processing 又有自己的原型。身份表单可在无耳标/耳缺、仅填性别或重量时 Save。

建议 Piglets 行/选择统一用新版 Row；身份必须有耳标或耳缺。Care 和身份是留在母猪 Actions，还是转到独立 Piglet processing，需要在这里定。

4 · 仔猪死亡有两套记录方式

母猪记录的 Record dead 已有七个原因；旧 Piglet records 的 Report mortality 另有原因选择，且保存映射会把 Other/未知原因算成 Put down。

待确认 · 一张死亡表单

现有两张表单承担的信息不同：一张知道具体仔猪 ID，另一张按原因计数。

建议以 Record dead 的七原因与白卡片为统一基础，并在同一流程保留 ID 与无 ID 数量。先修正旧表单的错误原因映射，不让 Other 写成 Put down。

5 · 锁定后仍有旧的“Correct piglet count”

11 月 3 日的规则让 Born 在 Finish 后冻结、Undo 只在 Farrowing log；Actions 里的 Reconcile 仍能直接保存一个新 Alive 数。

待确认 · 重数的入口

PRD 指向独立 Count 功能，但这个功能没有已批准的屏幕；旧 Edit-record round 只有草案。

建议 Reconcile 在 Actions 保留原位灰显，说明需等 Count 功能；当前页不再改变锁定的 Born。Count 的完整入口另开画布决定。

6 · End task 的 outcome screen 重放成 Ready

farrowing.task-outcomes 的当前 preset 仍有 8 头 Awaiting 母猪，所以实际运行态是 task-ready；这是 71 页逐页重放发现的错配。

建议 · 一页一态

如果保留独立 task-outcomes screen，preset 应真的落在此态；若它与 task-complete 无独立用途，可删掉重复 screen。

绩效卡同时要把 Put down 和 Other 分开计入；当前统计把第 6 槽当成 Other。

7 · Death breakdown 已没有入口

Atlas 的 farrowing.death-breakdown 仍尝试点 “Death causes”，但完成记录已无该控件；新版 Details 直接写出各死因。

建议 · 清理旧门

按 11 月 3 日的一页 Details 版本，移除旧 Death breakdown screen 和失效重放；补上 details-first 的真实入路。

Finished / Sow died 的详情仍用同一套现行内容。
