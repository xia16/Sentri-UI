# Task drawer action placement: Mobbin observations

Research date: 17 September 2026. These observations concern the specific screenshots inspected, not every version or screen of each app.

## Observed references

- [Todoist task sheet](https://mobbin.com/screens/131fe373-2208-4c8f-933b-b6047a92fb68): Deadline, Location and Move to appear as small outlined buttons with inline icons and text, within the task's content. Additional actions use an ellipsis in the header. This screen does not show a bottom completion button.
- [GitHub issue sheet](https://mobbin.com/screens/88ab3671-49a9-4fd9-8788-45b83214500e): Edit links are aligned with individual section headings, including Assignees, Labels and Milestone. Editing is attached to the information it changes.
- [Deepstash journey sheet](https://mobbin.com/screens/147f4039-2ca6-4d89-9afd-4d368439b54d): A compact outlined Listen button sits beside a larger filled Start Journey button at the bottom. This is a useful two-button footer reference; it does not represent Back navigation.
- [Apple Fitness workout sheet](https://mobbin.com/screens/3f826ed9-77a8-43c5-9ce9-b9aad18f90e6): Workout controls and End Workout, Check In and Lock Controls use visibly bounded buttons. This is a denser action sheet, not the recommended composition for our small set of secondary record actions.

## Interpretation for Farrowing

The current three icon-over-label shortcuts resemble a tab bar even though they open actions. Stacking them above a second footer makes both rows compete for attention. Reducing icon and text sizes does not resolve that ambiguity.

Recommended next visual iteration:

1. Keep farrowing execution in its medium drawer.
2. Place Edit, Record death and More actions together near the litter summary, as one row of lightly outlined buttons with icons beside their labels.
3. Keep Back and Finish farrowing together in the fixed bottom bar.
4. Preserve visible labels and at least 44 px tap areas. Do not keep shrinking the text.
5. Keep More actions grouped with Edit and Record death, as requested, rather than moving it to the header.

The proposal adapts these observed patterns to the user's navigation convention. The references are not evidence that every mobile app follows one universal layout. No prototype changes were made in this research pass.
