One list, three tasks.

The unified task list rendered through the synthesized VI, across the three most different tasks it must serve: a sweep with bulk marking (heat check), a per-sow sequence with payload actions (breeding), and long-running records with live alerts (farrowing). Statuses are the production set only, refined in copy. Color appears exactly where a status is stated — nowhere else. All numerals are mono. Nothing is saved, submitted or completed on a room screen — actions commit themselves.

01 · Task lists — every task through one list

Header · lens · pen-grouped rows · dock — configured, never forked · swipe →
How this section works

All eight production tasks rendered through the same list. What varies is only configuration: the unit KPI in the header, the lens partition, the row's status vocabulary and optional memory line, and whether rows carry a checkbox (only when the mark is stateless and the bar can express it). Weaning and piglet processing are pen-level — the row is the litter, keyed under its pen and sow. Piglet processing splits its two kinds of work honestly: treatments (iron, drops, teeth, tail, castration — done to a whole litter, no data captured) appear in the memory line as what is left only — done ones are history and live in the record — and are bulk-markable from the bar; tag / notch / weigh is per-piglet data entry, so it is reached by tapping the row: the litter record holds both the treatment checkboxes and the per-piglet tag/weigh page, as production does — never a bar action, never a second row button. Time-boxed tasks (heat 3 d, return-heat 7 d, pregnancy 3 d) show day n of N under the task overview — the whole-task fact that changes how fast a hand moves. Return-heat is a watch task — the cohort never shrinks and returning is the unwanted outcome — so its progress is days: 3 / 7 days with a seven-segment day gauge, and 2 returned as a side fact, mirroring production's day dots. Nothing else was invented.

01b · The row — anatomy and data grammar

Fact · escalated chip · metadata tokens · rail — one grammar, eight tasks

The unified convention
Fact (line 1) — words. The animal's cycle position as a readable phrase — space is free on line 1, so spend it on clarity: Mated 21 days ago · Due in 5 days · Signs · 10h ago. Past events read elapsed, scheduled read until.
Metadata (line 2) — tokens. Space is scarce, so compress: mono, lowercase, · separated tokens (started 6h · parity 3), fixed order time → counts → codes. Open rows carry only relative times and counts — no clock stamps. Two registers, one rule: words where there is room, tokens where there is not.
Stamps. Jul 8 · 07:14 · G.H · JY001 are record trails: they live on done rows, and on an open row's metadata line when its state descends from a prior record (signs 10h · G.H, unclear Jul 5 · G.H). Working judgments stay elapsed; records stay absolute.
Chip law. A chip is the reason this row needs you first — an escalated measurement (LAST 45M) or a flagged observation recorded by a hand (SIGNS). Below threshold, measurements stay grey tokens; the flag's trail (who · when) lives in the metadata line. Picker cells: the pen's one statement. Nothing else is a chip — filter options and lens segments are controls; done outcomes are grey text + ✓; peek mirrors the row.
Rail. Box tasks: empty — the bar acts. Rail tasks: verdict word + › — the tap acts. Done: ✎.
Template. Two lines, every row, every task — one height, one rhythm across the product.
Lens law. Segments name the pig's state — never an action verb — using the most specific truthful word: a biological state where one exists (Not in heat / In heat, No return / Returned, Open / Mated, Awaiting / Active), and Unchecked / Checked as the floor where completion produces a record, not a state (pregnancy's three outcomes, postpartum, weaning). Consistency lives in position, not vocabulary: the first segment is always the working pile, the second always the finished pile, All always last. Length rules: copy budget ≤ 12 characters at 3 segments, ≤ 8 at 4 (中文 never binds); segments hug their content instead of splitting into equal thirds; when space still runs out, inactive segments drop their counts — the active one keeps its; four states is the ceiling — a fifth is a sub-lens or a filter dimension, never a segment; ellipsis on a status word is banned.

02 · Pen picker — one component, every task

Map = truth · tap = land · long-press = peek · never acts · swipe →
How the picker works

The map of the unit, for one question: is there work for me here, how much, how urgent. A cell is a pen code and, at most, one chip — the same chip the rows use for important facts. Chips exist only for states that ask for a hand: red overdue, amber attention (signs · due today · interval), green ready. Green means go; done is a ✓ beside the pen code with the outcome in muted text (6 mated · 11 born · 4 in heat) — a glyph, not a colour, so green never means two things. States that ask nothing (wait 9h · due 3d · next 2d) are grey text; farrowing active is a neutral chip. Counts lead the word (3 SIGNS) and appear only from 2; durations always carry a unit. Text is ink; only chips carry colour; no legend. 75% sheet, 24 pens without scrolling; wider units pan with the column header fixed.

Rules: truth · land · never acts · peek
The map is truth; the lens is a view. The picker never inherits the lens or the filter — every pen shows its real state. A dimmed cell means exactly one thing: no pigs from this task in that pen. It is never a side-effect of what you filtered.
Tap = land. Sheet closes, the list scrolls so that pen's header is pinned at the top, rows beneath. If the current lens hides what you came for, the pinned header says so and flips the lens in one tap (PEN D3 · 4 in heat · show in "In heat" ›). Dimmed pens are the only ones that would need "All", and no one taps those in a task — so the picker never has to reach it.
The grid never acts. Considered and rejected: cell-level quick actions. They work for pen-level tasks (piglet processing, weaning) and are ambiguous for individual ones (which sow?), so some cells would commit and some would not — every tap becomes a question, and a mis-tap in gloves becomes a wrong record instead of a wrong scroll. Pen-level quick actions live in the pinned pen header of the table instead (PEN A2 · 8 piglets · Iron done): one tap after landing, on the surface that already commits, with the litter visible.
Long-press = peek. Hold a cell ~350ms and a small read-only card lists the pen's rows (tag · status); release and it's gone. No checkboxes, no actions, never required — an accelerator for "which three are ready?" before walking. Plain pointer timing, no native component.

02c · Peek — long-press a pen, see inside, release

Read-only · anchored to the cell · plain pointer timing · swipe →
How the peek works

Hold a cell ~350 ms and a card rises from it: the pen's rows exactly as the table renders them — same component, read-only: no checkbox, no › — capped at five with +N more. Anything you want in the peek, you put in the row; there is one place to manage. Release and it is gone; the picker underneath is untouched. Nothing in the card can be tapped, ticked or committed: it is a look before walking, not a screen. Tap the pen instead to work it. Built from an ordinary positioned card and a press timer; the tap-to-land fires only if the press ends before the timer, so the two never collide.

Piglet processingThe dense one — treatments as a strip per litter

Production tracks eight treatments per age-day. The peek shows only what is left per litter — amber = due today, plain = later; done treatments are simply absent, and a finished litter is a ✓. Day-age sits once in the header, not on every row. That is enough to decide whether to walk in with the teeth clippers or the tagging kit — the record itself, with its checkboxes and sub-forms, stays in the table.

BreedingSequence memory per sow

One line per sow — which mating, and its one relevant fact (2nd mating · interval 5h) — with the ready chip; waiting sows dim, done sows ✓. Answers "which three are ready and do I have doses for them?" from the doorway.

Heat checkThe plain one

Signs sows first, just their recency beside the chip; the rest dim. Often the peek is enough to skip a pen entirely (four signs → definitely walk; one due → maybe later).

Why read-onlySame reason the grid never acts

The moment a peek can commit, every long-press is a risk in gloves and the picker becomes a second working surface. Read-only keeps the rule a farmer can trust: the map only ever points.

The filterOne question decides the strip vs the sheet

Does this change what a hand does at the pen right now? Only whole-task progress passes — so only that is on the room screen. KPI, configuration, SOP, status legend and End task all fail it, and all live here, one tap away. The sheet exists so nothing has to leak upward.

StructureProduction's 任务详情, compressed

Same sections as production, in the same order — progress, KPI, configuration, SOP, end — as a bottom sheet over the room: the worker never leaves the pen list. Production's 状态说明 legend is retired — the rows' status words and 01b's grammar made it dead weight. Numbers are mono and large; labels quiet; SOP is a link. The per-unit split is the one addition, because it is how Unit B knows Unit A is done. Configuration is the task's own shape: cadence and window for sweeps, sequence rules for breeding, the treatment schedule by day-age for piglets.

End taskWhere completion actually lives

Bordered red, at the bottom of the sheet — reachable, never accidental, and one level above any room. Sweep tasks show it always; standing tasks (heat check) show it as the supervisor's stop; event tasks (breeding, farrowing) never show it — they close themselves record by record.

CopyNames the batch, not "task"

Header reads "Batch wk 32 · day 1 of 7". "Task" was a system word; the batch is what the farmer calls it. The room strip drops the word too — "62 / 100 in heat · 3 rooms" is unambiguous once the destination is this sheet.

04 · The record sheet — shell and field kit

One component · ten fields · fifteen events
What this is and why it comes first

Every sheet in 04b is the same shell with a different field list — we drew it nine times before naming it. This section names the shell, closes the field kit, and shows the fifteen events that compose from it without new design. Six of the ten fields are already in use; four are new. Once the kit is fixed, adding an event stops being a design task and becomes a data task: a field list, reviewable as a table row.

Scan = selectThree ways to say which pig, one way to say what

Checkbox, scan and search all do the same thing: put a sow into the selection. Scanning 000319 scrolls her pen into view, ticks her box, tints the row for a moment with a small "scanned" mark, and the dock swaps to the action bar — identical to a tapped box. Scan the next sow and the count grows; tap an action and the marks commit, bar clears, dock returns.

Why not a scan screenThe list stays the surface

A dedicated "scanned pig" page would be a fourth way to mark, with its own buttons and states. Landing in the list instead means the farmer sees the sow in her pen context, her neighbours, and the same two buttons they already know. Scan-scan-scan-Mark is a loop that never leaves the screen.

Dock rebuilt48px everywhere; scan is the biggest thing

The footer text labels were 10px mono — unusable in gloves. Now the dock is one row: pen chips scroll on the left, search and scan are 48px chips pinned right, scan filled ink because it is the action farmers reach for most. Grid dropped — chips + scan + search cover navigation; a pen-map returns only if a room's shape ever demands it.

Tasks without checkboxesScan opens the record

Breeding and farrowing have no bulk marks, so there scan skips selection and opens the sow's sheet directly — the only action that exists for her. Same tool, same place in the dock, resolves to whatever the task's one action is.
