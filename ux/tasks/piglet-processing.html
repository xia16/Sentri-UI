Piglet processing · 仔猪处理

The heaviest task in production — an age-day treatment schedule (1/2/3/5/7 日龄), eight treatment types, per-day checklists with a submit ceremony, a per-piglet identity sub-record, and a four-dialog count-reconciliation flow — re-expressed as one list, one bulk sheet, and one litter record in which every mark commits itself. The honest split survives everything else: litter-level treatments are bulk; per-piglet data entry is never bulk.

3 · Subtraction analysis

Production elementVerdictJustification
Five age-day accordions + 提交结果 submit + success toastCUTThe checklist is a form pretending to be a room. Our law: actions commit themselves; no Save/Submit on any screen. Each treatment mark commits on tap; the "day" is a derived grouping, shown as a schedule strip with stamps, not five collapsible forms.
Treatment icon strip on rows + 3-colour icon semantics + corner-check badgesCUTMicro-icon states in glove distance are unreadable, and the legend needed an annotation to explain itself. The row's memory line lists what is left in words（teeth · tail · castrate · tag/weigh）— done is simply absent; history lives in the record (01b, already rendered).
Dual pig-List / pen-Grid viewsCUTThe grid is the list re-drawn as cards, same taps. Pen picker (02) + peek (02c — already renders the per-litter remaining-treatments strip) + dock cover spatial navigation; grid never acts.
状态说明 status legendCUTA legend that explains status words is the words failing. day 3 · due / next in 2d / All done say it themselves (01b grammar).
Info banner（共 200 栏 · 请标记…）CUTRestates the header count and the task's name. The header cell already carries 100/200 pens.
Filter: 状态 dimension · 排 dimensionCUT状态 is the lens (Due today / Done / All); 排 is Go-to-pen. Both already subtracted in 01c, which keeps the two real extras: treatments-due-today + day-age.
倒计时中 as a filter stateMERGE"Counting down" = not due yet = the All lens minus Due today; the day-age filter covers any finer slice.
Per-item recorded-by + timestamp linesKEEPAttribution is a law. Rendered as stamps on done items/rows（Jul 8 23:00 · G.D）, not as avatar rows doubling every item's height.
Future-day pre-fill（可提前填）KEEPReal barn need (do day-5 work while hands are on the litter). In a self-committing model it needs zero UI: marking a treatment before its day just records it, dated; the schedule strip shows the early stamp.
“提交后不可再查看” on tag/notch/weighCUTContradicted by production's own ended-state piglet list, which shows the data read-only. The rule is an entry-form artefact. Ours: data always viewable (piglet table), corrections via ✎, audited (04 "Edit a done row").
Sub-form states 已填写/未填写 on the checklist itemMERGEBecomes the tag/weigh line's own memory: tag/weigh · 9 of 20 — a count, not a state word pair.
Count-confirm dialog ×3 + 补录仔猪 dialogMERGEFour dialogs, two entry points, one job: reconcile observed vs system count. One inline step in the litter record: count row shows system number; tap → adjust → if different, reason + confirm, system reconciles. Same fields, one surface.
公猪/母猪数量 steppers + per-piglet sexMERGESex counts derive from identity rows when the litter is fully rowed; steppers only asked when it isn't. Never ask twice for the same fact.
出生整窝体重 backfill promptKEEPFarrowing-owned datum, but the amber backfill line in the litter record is the last realistic chance to get it. One line, only when missing.
仔猪信息 tab as a second tabMERGEThree facts (age · count · birth weight) don't earn a tab; they are the litter record's header block. Age is derived and already in the row.
更多操作: foster · death · count anomalyMOVELitter lifecycle events, not processing marks — stay one ⋯ behind the litter record header, shared with weaning's litter record. 数量异常 folds into the count row (above).
母猪流产 in the more-sheetCUTAn abortion entry on a farrowed litter's processing record is a copy-paste leftover from the pregnancy stage.
Scan FAB + search by tag/notchMERGEInto the dock (01): Go to pen · Scan ear tag · search. Delta: scanning a piglet's tag resolves to its litter.
End-task pages: consequences + acknowledge + farrowing blockKEEPThe one legitimate ceremony — it destroys the ability to backfill. Lives behind the task detail sheet (03), never on a room screen. Consequence totals derived.
Task-ended fork: separate list/detail/filter/record screens ×6MERGENot new screens — the same list (Done lens · read-only rows · ✎ off), same litter record (marks frozen, ! on gaps), same detail sheet (已结束 badge). The 全部/部分/未完成 segmentation is the lens plus a partial flag; last-processing-date filter joins 01c for ended tasks.
On-time KPI（准时率）KEEPAlready the unit KPI in our rendered header (01: 90% on time · ≥90%).
Pens without a task listed（A4 无任务）+ no-task litter stateKEEPPhysical completeness — the All lens shows them dimmed; the empty record state dies with the tabs.

Deltas — the only new design this task needs

DeltaSpec
1 · Schedule strip on the litter recordReplaces five accordions: one row of day dots（d1 ✓ · d3 ● · d5 · d7）, today auto-focused. Tapping a past/future day reveals its stamps / pre-fillable checks. Derived from config; planned dates computed, never typed.
2 · Pad fieldsThe rendered pad (tag · weight, auto-increment, scan override) gains notch as an alternative identity (picker) and a sex toggle per piglet. Running list = the read-only piglet table; unidentified count rides the line（9 of 20）. Foster-source litters show the one amber inaccuracy note.
3 · Litter facts blockCount row: system number shown; tap → observed count; mismatch → reason + confirm, auto-reconcile (merges production's 4 dialogs). Total-litter-weight input at the weigh day. Birth-weight amber backfill line only while missing.
4 · Litter overflow ⋯Foster and report-death entries on the litter record header — shared component with weaning's litter record.
5 · End-task consequences pageBehind 03's End task: unfinished-pen count + head totals (derived), "cannot backfill" statement, farrowing-dependency block, acknowledge checkbox → red confirm. Non-mandatory flag (console) only changes the copy, not the ceremony.

6 · Open questions

QuestionWhy it matters
1 · Is “提交后不可再查看” a compliance rule or a form artefact?We replace it with always-viewable data + audited corrections. If a real rule (e.g. anti-tamper on identity records), corrections need a permission gate instead.
2 · Non-mandatory task: do unfinished litters stay amber-overdue until task end, or expire quietly at weaning?Decides whether the Due lens can ever be noise on farms that skip treatments by design.
3 · Count mismatch: production auto-adds/removes heads with only a free-text reason — should a removal require picking a cause (death vs count error) so mortality stats stay honest?Auto-removed piglets silently bypass the death-reporting flow that exists one button away.
4 · Cross-task jump (designer's own note): postpartum check and piglet processing hit the same pen in the same days — one combined walk, or a jump link between the two records?Two visits to every pen vs one; touches the task model, not this screen set.
5 · Day-age filter lists 1/2/3/4/6/7/≥8 while the schedule is 1/2/3/5/7 — are filter values config-driven or fixed?A fixed list will drift from any farm's console schedule; we assume config-driven.
6 · Fostered-in piglets without identity: allow identity rows flagged inaccurate (production's warning) or block until origin is resolved?Determines whether the pad needs a per-row foster flag.
