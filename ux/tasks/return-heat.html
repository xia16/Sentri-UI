Return-heat check · 返情检查

Thesis: production spends 13 screens, an 8-word status vocabulary with a legend (three entries of which the designers left as XXXX), a two-step submit ceremony and a parallel grid view to collect exactly two facts per sow: shows signs of return and has returned. Everything else — expected-return dates, day windows, day dots, rates, batch consequences — is derived. Our list already renders this task; the genuine deltas are the batch-consequence surface and the signs carry-over rule.

2 · Requirements distilled

Data captured (the farmer's hand)

FieldTypeNotes
Signs of return · 有返情迹象flag (per sow, per check)Repeatable across checks; "unstable" observation, sow stays in batch. Auto: recorder + timestamp.
Returned · 已返情terminal mark (per sow)The one consequential fact: sow is not pregnant → leaves batch, rebreed. Auto: recorder + timestamp.
Correction of either markedit, auditedProduction: 修改状态 unlock → re-pick. Requirement is edit-with-audit, not the two-step lock.
Round certificationassertion (per pen / per round)Production: one 提交结果 per unit; unmarked ⇒ 未返情. The data requirement: an explicit "rest seen, no return" assertion so negatives are claims, not silence.

That is the entire capture surface. No numbers, no text, no photos. (The sheet's [⋯] menu contents are unspecified in this section.)

Derived by system (never asked)

Per-sow expected return date 预计返情 = her mating date + config start-day (18). Day counts ("day 20", "in 5 days"), window entry/exit, 返情窗口/返情期间/监测期内 phrasing — all one derived number dressed eight ways.
Day gauge (day n of N), per-day check count, missed days (amber dots).
Group counts: not-returned / signs / returned / unchecked; per-unit and per-pen aggregates; grid card states.
Return rate % vs target; KPI refresh (production: on submit — annotation "每提交一次结果，刷新一次KPI"; ours: live).
Batch consequence: returned → 移出批次 → rebreed cohort (spawn rule); not-returned + signs → carry with batch to pregnancy check.
No-data state 获取不到状态 (missing mating record ⇒ no expected date); 未配种 exclusion (sow in room, never bred ⇒ not in cohort).

Configuration (per farm / per task)

Deltas (all that needed design)

1Returned-row stamp carries its consequence: out of batch · rebreed queued. Production buried this sentence in a legend and a submit screen; it belongs on the record trail the moment the mark commits (undo window applies, marks commit themselves).
2Watch-task round semantics: a day segment certifies when that day's configured rounds (2×) have their pens confirmed. Signs flags persist across checks until the window closes or the sow returns; at window end unreturned signs-sows simply stay with the batch, flag rides their trail into pregnancy check.
3End-task confirm for return-heat gains the two-group consequence summary (stays with batch → pregnancy check / moved out → rebreed) — the only task-specific content in an otherwise standard end-task sheet (sweep task ⇒ End task lives in detail sheet only).

6 · Open questions

1Second pass reality. 第2次返情检查 exists in config with placeholder-identical values (both "day 18"). Do farms actually run a second watch (e.g. day 39–45, second cycle), and is it a separate task instance on the shrunken batch?
2When does "returned" bite? Production removes the sow from batch only at 提交结果. We commit at mark time with undo. Is instant batch removal (rebreed queueing) acceptable, or must removal wait for a round boundary for compliance reasons?
3Day certification with 2 checks/day. What makes a day green — both rounds confirmed, either one, or presence by the configured times? (Production's amber dots imply missed days are tracked; the rule is nowhere stated.)
4Signs at window end. A sow flagged signs on day 7 but never returned: does she carry to pregnancy check silently, or should the flag force an early/priority pregnancy check (production's "unstable" wording hints at this)?
5Sheet [⋯] menu. Contents unspecified in this section (sow card? health report?). Confirm scope before assuming.
