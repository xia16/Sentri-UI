Breeding · 配种

Event-driven, per-sow sequence task: each in-heat sow must receive N configured matings at a configured interval, each mating stamped with a semen batch (or boar), operator and time. Production spends 27 frames mostly on navigation, duplicate confirmation and an archive clone; the record itself is one timeline sheet our system already renders. The genuine deltas are the semen picker's rules, the extra-mating entry, the scan-guard branches, and what happens to un-mated sows when the batch's breeding phase closes.

Deltas — the only new design work

Δ1 · Semen picker rules. The picker sheet itself is standard; the rules are task-specific: list sourced from the console breeding plan (semen batches or boar IDs); search + QR scan of the dose label; default = previous mating's batch; changing at mating k forward-fills the default for k+1…; always editable. The confirm button always names the batch, so the default is visible at the moment of commit.
Δ2 · Extra-mating entry. A done sow's sheet grows one ghost timeline row + Add mating N+1. No new screen, no new list state; numbering and interval logic continue.
Δ3 · Guard sheet. One sheet composes production's B–F: up to two factual notices (not in unit · not in batch), the pig card, a location line, and actions built from three verbs (confirm location / join batch / breed). The not-in-heat dialog chains last and back-fills the heat record with attribution. Batch-join verification = scan the ear tag (type last-4 fallback).
Δ4 · Phase close (console). Breeding keeps no End button on the phone. The console's batch view shows the derived close preview — sows at target, mated-but-short, un-mated (will leave the batch) — one confirm, disabled with inline reason until heat check is closed. The typed head-count is gone; the system already knows the number.
